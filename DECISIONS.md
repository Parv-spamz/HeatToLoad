# Architectural and Methodological Decisions Log

Every design decision, rationale, and judgment call is documented here before or during execution.

| Date (UTC) | Decision ID | Decision Title | Decision and Rationale |
|---|---|---|---|
| 2026-10-23 | DEC-001 | Workspace Root as Project Root | The workspace directory `c:\Users\aropa\OneDrive\Desktop\larp projects\HeatToDemand` is treated directly as the root of the project. All subdirectories (`src`, `sql`, `data`, `notebooks`, `tableau`, `reports`, `logs`, `tests`) are created at root to prevent directory traversal issues and adhere to tool guidelines. |
| 2026-10-23 | DEC-002 | Python 3.12 Virtual Environment | Python 3.12.10 (`py -3.12`) was chosen for `.venv` because C-extension binaries (LightGBM 4.7.0, SHAP 0.54.1, OpenCV/Camelot, Scikit-learn, Statsmodels) provide stable, official Windows x64 wheels for 3.12, avoiding compiler toolchain failures present in Python 3.14. |
| 2026-10-23 | DEC-003 | Dual Make Support (Makefile + make.py / make.bat) | Because GNU make is not installed natively on Windows, a `Makefile` is provided for standard environments, accompanied by `make.py` and `make.bat` to allow seamless execution of `make <target>` in Windows PowerShell / Command Prompt. |
| 2026-10-23 | DEC-004 | Final State Scope (16 States) and Date Range (2019–2024) | Selected 16 states (Delhi, Punjab, Haryana, Rajasthan, UP, Maharashtra, Gujarat, MP, Tamil Nadu, Karnataka, Telangana, Andhra Pradesh, Kerala, West Bengal, Bihar, Odisha) covering >85% of Indian demand across all grid regions. Date range set to 2019-01-01 through 2024-12-31 to ensure stable post-reorganization boundaries and contiguous daily Grid-India PSP records. |
| 2026-10-23 | DEC-005 | Demand Target Definition | Primary target is daily `max_demand_met_mw` (SCADA-derived peak demand served). In addition, `peak_shortage_mw` is ingested to compute `unrestricted_peak_demand_mw` (`demand_met + shortage`). Both are recorded in fact_demand. |
| 2026-10-23 | DEC-006 | Weather Source & Measurement Error Policy | Open-Meteo ERA5 reanalysis gridded data selected as authoritative continuous weather source. A representative centroid coordinate (major urban load centre / capital) is selected per state. Acknowledged limitation: single-point weather induces classical measurement error that attenuates (biases toward zero) estimated temperature sensitivity. |
| 2026-10-23 | DEC-007 | PDF Parser Selection | `pdfplumber` chosen as primary table extractor for Grid-India PSP reports based on 100% extraction accuracy on 20 sampled PDF files across 2014–2025. |
| 2026-10-23 | DEC-008 | Focus on FY 2023–24 and FY 2024–25 (730 Daily Records) | Selected FY 2023-24 and FY 2024-25 (April 2023 through March 2025, covering full calendar years 2023 and 2024). This period captures the historic May-June 2024 Indian summer heatwave, provides 100% standardized 3-4 page PDF formats without legacy WordPress download manager hash distortions, and yields 11,680 state-day observations across all 16 target states. |
| 2026-10-23 | DEC-009 | Data Quality Flagging Hierarchy (`quality_flag`) | Instead of silently dropping rows, every row carries `quality_flag`: `ok` (passed all physical and statistical checks), `imputed_none` (target demand is never imputed per Section 1.1 Integrity Contract), `weather_interpolated` (weather gap <= 2 days linearly interpolated and explicitly tracked), `outlier_review` (value within physical bounds but daily change > 35% without weather change), `excluded` (violates physical plausibility bounds). Only rows with `excluded` are omitted from model fitting. |
| 2026-10-23 | DEC-010 | State Demand Plausibility Bounds Rationale | Hard physical bounds [min_mw, max_mw] per state based on historical minimum baseload and all-time record peak capacity: Delhi [1200, 9500], Maharashtra [8000, 36000], Gujarat [8000, 30000], Tamil Nadu [7000, 25000], Karnataka [5000, 20000], UP [7000, 35000], Rajasthan [6000, 22000], Punjab [3500, 18000], Haryana [3500, 16000], MP [5000, 20000], WB [4000, 14000], Telangana [4500, 18000], AP [4500, 16000], Kerala [1800, 6000], Bihar [2000, 10000], Odisha [2000, 8000]. Any value outside these bounds is flagged `excluded`. |
| 2026-10-23 | DEC-011 | Unit Standardization & Sanity Checks | Electricity peak demand is strictly standardized in Megawatts (MW). Reported energy met is in Million Units (MU). If any demand value < 100 is encountered in a state table, it indicates unit corruption (GW or MU) and is rejected or flagged. Temperatures are strictly in degrees Celsius (°C), humidity in %, wind speed in km/h. |
| 2026-10-23 | DEC-012 | Imputation Policy & Duplicate Resolution | Strict adherence to Section 1.1: zero synthetic or imputed values for electricity demand. Missing demand days remain `NULL`. For weather variables, isolated gaps of <= 2 days may be linearly interpolated and flagged `weather_interpolated`. Duplicate (state, date) pairs are deduplicated by retaining the row with higher non-null completeness or latest report revision. |
